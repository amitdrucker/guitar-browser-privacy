Guitar Browser privacy policy

Updated: 28 October 2026. Developer: amit drucker. Contact: amitdrucker@gmail.com.

Guitar Browser lets you browse websites, including Tab4U and Ultimate Guitar. Standard browsing and song tools run locally. There is no app account, analytics SDK or advertising SDK. The public production version does not enable shared sessions. The internal-testing pilot can optionally connect to the developer’s sharing service under the policy below.

Bookmarks and script preferences are stored on your device. Android WebView stores cookies, cache and website storage locally, including website login sessions. The application disables Android backup. Removing the app removes its local application data.

Websites receive requests you make through the browser, which can include your IP address, browser information, search queries, cookies and information you submit directly. Text searches use Google. Websites can display advertising or process data according to their own policies. Ordinary browsing does not send browsing history to the sharing service. This is not a promise about the websites' data collection.

Clear browsing data, available in the browser menu, removes cookies, website storage, cache, form data and browsing history and signs you out of websites. It retains bookmarks and per-site script preferences. Remove bookmarks with the page bookmark button. Clear all app data in Android Settings to remove all application preferences and bookmarks.

The bundled Tab4U 4.8 and Ultimate Guitar 0.04 scripts and the authored Shironet, Negina and Nagnu readers execute locally on supported websites and ship with app updates. They transform displayed song content and add reader controls without uploading song text. Optional shared sessions separately transmit the state described below. There is no native JavaScript bridge or remote script update mechanism.

The only requested Android permission is Internet access. Cleartext HTTP, mixed content, file/content access and third-party cookies are blocked. Website processing and Internet browsing are governed by their respective privacy policies.

Website accounts and subscriptions are managed by the website provider. Use that provider’s account deletion controls to remove its account or server data. Website retention policies govern information already sent to websites. The developer does not sell browsing data.

Optional shared-session pilot

Starting or joining a session connects to the developer's Cloudflare-hosted service. Creating a session on Home initially sends no song state. Once the host opens a supported ready song, the host sends its URL, normalized vertical reading position and effective transpose. Viewers receive that state. No song text, website cookies, passwords, browsing history, bookmarks or website account data are sent by the sharing transport. The song URL itself can reveal what the host is reading, including its query or fragment, so share only pages you intend viewers to see.

No account is required. Anyone holding the invitation can join while it is valid, subject to the 25-viewer capacity. Treat invitation links and QR codes as access credentials. Joining issues a separate temporary viewer credential. Host, viewer and invitation credentials are kept in app memory; the backend stores hashes rather than raw credentials. Credentials are sent in HTTPS authorization headers. The invitation credential is in its URL fragment and is not sent in the landing-page request.

The service retains the latest reader state, status, revision, session expiry and recent viewer heartbeats. It keeps no application-level song history. Sessions expire after 24 hours. Stop revokes the invitation and deletes the live session record once the server acknowledges it. If Stop fails, the app retains retry controls; closing or uninstalling the app does not confirm server deletion. Cloudflare infrastructure recovery copies and metadata are governed by Cloudflare's policies; immediate physical deletion of backups is not promised.

Cloudflare necessarily processes connection information, including network addresses, to serve requests. For abuse protection, the Worker hashes the Cloudflare-provided source IP address and uses that key in Cloudflare rate-limit counters. Raw IP addresses are not stored by the application. A separate pilot counter stores only the cumulative number of creations. Worker request logging/observability is disabled, and application code does not log invitation credentials, API payloads or full song URLs. This does not promise that Cloudflare processes no infrastructure metadata.

Opening a song still connects to that website under its own policies. Shared sessions do not transfer the host's website login to viewers. Copy, QR and WhatsApp/share-sheet actions disclose the invitation to the recipient or chosen service. The invitation landing page has no analytics, external assets or session-fetching script.
